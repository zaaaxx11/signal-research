## Goal

Make five existing surfaces feel finished without changing the data model: shareable news filters, a calendar that can show all of a day, CSV in/out for the two local pages, and moving averages on the chart.

## Current context / assumptions

The product is a Finviz-shaped equity surface over a scrape-first engine. Every nav section has a real page; there is no placeholder route left.

Facts an implementer must know before touching anything:

* **Frontend lives in `web/`**, React 18 + TypeScript + Vite, base path `/app/`. Gate: `cd web && npm run check` (vitest + `tsc --noEmit` + build + token audit + bundle budget). **Never run a dev server on `:8099`** — that is production; use `:5173` or an ephemeral port.
* **Backend lives in `app/`**, FastAPI. Python gate: `.venv/bin/pytest -o addopts="" -q`. Production is `ztockz.service` on `127.0.0.1:8099`; tests must never restart or write it.
* **Persistence for the two local pages is `localStorage`.** There is no account, no server state, no sync. Any CSV feature stays client-side.
* **The chart geometry is pure and already tested** (`web/src/charts/geometry.ts`); painting is one 2D pass (`web/src/charts/paint.ts`); the component (`web/src/charts/Chart.tsx`) owns the canvas, the range buttons and the hover readout.
* **The calendar payload caps each day at 50 symbols** (`BUCKET_LIMIT = 50` in `app/api/calendar.py`) and reports the true count separately. The page prints `+N more` and stops — that is the dead end this plan fixes.
* **The news page filters client-side** (`web/src/news/NewsPage.tsx`, `useState` at line ~219) and does not read the URL, so a filtered view cannot be shared.
* **The shell owns routing and URL state** (`web/src/shell/routes.tsx`): `useSearch()` returns `window.location.search`, and `navigate()` writes history. Read it, do not invent a second router.
* **House rules that fail the suite if broken** (they are tests, not conventions): `app/api` may not import a URL/transport library or another route module (`tests/test_import_direction.py`); every broad `except` must be in `app/engine/audit_allowlist.txt` (`tests/test_engine_audit.py`); `web/src` may not contain hex colour literals outside `tokens.css` (`npm run audit:tokens`).

/** A ticker as the URL may carry it: 1-12 letters, digits, dot or dash. */
const SYMBOL_PARAM = /^[A-Za-z0-9][A-Za-z0-9.\-]{0,11}$/;

/**
 * The `?symbol=` value, or `""`.
 *
 * The filter box is a text field for humans; the URL is an input a stranger
 * writes. A value that is not shaped like a ticker is ignored rather than
 * passed to the filter, so a shared link cannot smuggle a 4 KB string into a
 * field that then repaints 60 rows.
 */
export function readSymbolParam(search: string): string {
  const raw = new URLSearchParams(search).get("symbol") ?? "";
  return SYMBOL_PARAM.test(raw) ? raw : "";
}
```

// web/src/lists/csv.ts
import { MAX_SYMBOLS, normalizeSymbol } from "./storage";

/** A file a spreadsheet opens: one column, a header, a trailing newline. */
export function toCsv(symbols: readonly string[]): string {
  return ["symbol", ...symbols, ""].join("\n");
}

/**
 * Symbols from pasted text. Splits on newlines and commas, keeps the caller's
 * order, drops anything that is not shaped like a ticker, dedupes case-
 * insensitively, and stops at the quote limit — a paste cannot exceed what the
 * `/market/quotes` call can answer in one request.
 */
export function parseSymbols(text: string): string[] {
  const seen = new Set<string>();
  const out: string[] = [];
  for (const token of text.split(/[\s,;]+/)) {
    const symbol = normalizeSymbol(token);
    if (!symbol || seen.has(symbol)) continue;
    seen.add(symbol);
    out.push(symbol);
    if (out.length === MAX_SYMBOLS) break;
  }
  return out;
}
```

```ts
// web/src/charts/sma.ts
/**
 * A simple moving average, aligned with the input: index `i` holds the mean of
 * the `window` closes ending at `i`, or `null` while the window is still
 * filling. Nulls are kept, not dropped: the overlay must start where the average
 * exists, and a shorter array would silently shift every point left.
 */
export function sma(closes: readonly number[], window: number): (number | null)[] {
  if (!Number.isInteger(window) || window < 1) {
    throw new Error(`sma window must be a positive integer, got ${window}`);
  }
  const out: (number | null)[] = [];
  let sum = 0;
  for (let index = 0; index < closes.length; index += 1) {
    const close = closes[index];
    sum += Number.isFinite(close) ? close : 0;
    if (index >= window) sum -= Number.isFinite(closes[index - window]) ? closes[index - window] : 0;
    out.push(index + 1 >= window ? sum / window : null);
  }
  return out;
}
```

## Risks, tradeoffs, and open questions

* **URL writes on every keystroke (Task 1).** `replaceState` per character is cheap but shows in the history as one entry; using `pushState` would be worse. If the browser throttles, debounce at 150 ms — but measure before adding it.
* **One extra full request on calendar expand (Task 2).** The alternative (a per-day endpoint) is more code for a rarely used action. `per_day=500` makes a 21-day document ~10× larger; the ETag keeps repeats free.
* **CSV injection.** A symbol is validated by `normalizeSymbol`, so a cell can never start with `=`, `+`, `-` or `@`; the cost column is a number. Do not "helpfully" accept free text in the cost column.
* **Chart overlays are visual only.** They are not in the aria label; the hidden summary table stays first/last/high/low. Adding SMA to the label is a follow-up if a screen-reader user asks.
* **Deliberately not in this wave:**
  * *Header-click sorting in the screener* — the engine can order by three keys (`market_cap`, `turnover`, `gainers`) and nothing else; a header that toggles an unsupported column would be a lie.
  * *ETF-specific columns* (expense ratio, AUM) — the 116-column catalogue is frozen; adding columns is a separate decision.
  * *A market-wide insider feed* — needs an EDGAR full-index crawl; the current page reads Form 4 per company on purpose.
  * *A scan warmer* — the scan cache is keyed per (region, family, columns, floor, subtype), so "warming" means guessing every key a user might ask for. Measure the hit rate before building it.
